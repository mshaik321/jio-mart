## Deploy / redeploy procedure

Everything is built locally and shipped as artifacts — the server has no Composer and no Node, so `vendor/` and `public/build/` are built on the dev machine and uploaded.

```bash
# 1. Build locally
composer install --no-dev --optimize-autoloader   # (dev deps were included in the initial deploy)
npm run build

# 2. Ship the code (tar over ssh; rsync isn't available on the dev machine)
tar czf - \
  --exclude='.git' --exclude='node_modules' --exclude='.env' \
  --exclude='database/database.sqlite' --exclude='storage/logs' \
  --exclude='storage/framework/cache/data' --exclude='storage/framework/sessions' \
  --exclude='storage/framework/views' --exclude='public/storage' \
  . | ssh bigrock "tar xzf - -C /home2/innovx5x/shop.allsoft.online"

# 3. Migrate + rebuild caches on the server
ssh bigrock "cd /home2/innovx5x/shop.allsoft.online && \
  /opt/cpanel/ea-php83/root/usr/bin/php artisan migrate --force && \
  /opt/cpanel/ea-php83/root/usr/bin/php artisan optimize"
```

`~/.ssh/config` on the dev machine defines the `bigrock` host (key-based auth, no password).

**Never** run `migrate:fresh` or `db:wipe` against production.

### First-time setup steps (already done, recorded for reproducibility)

```bash
# Subdomain
uapi SubDomain addsubdomain domain=shop rootdomain=allsoft.online dir=shop.allsoft.online/public

# PHP version for the vhost
uapi LangPHP php_set_vhost_versions vhost=shop.allsoft.online version=ea-php83

# Database + scoped user (cPanel forces the innovx5x_ prefix)
uapi Mysql create_database name=innovx5x_groceryhub
uapi Mysql create_user name=innovx5x_ghapp password='<generated>'
uapi Mysql set_privileges_on_database user=innovx5x_ghapp database=innovx5x_groceryhub privileges=ALL

# Writable dirs (these are excluded from the upload, so they must exist on the server)
mkdir -p storage/logs storage/framework/{cache/data,sessions,views} storage/app/public bootstrap/cache
chmod -R 775 storage bootstrap/cache

# Storage symlink + scheduler cron
php artisan storage:link
(crontab -l; echo '* * * * * /opt/cpanel/ea-php83/root/usr/bin/php /home2/innovx5x/shop.allsoft.online/artisan schedule:run >> /dev/null 2>&1') | crontab -
```

## Queues

Shared hosting can't run persistent `queue:work` daemons. V1 runs `QUEUE_CONNECTION=sync` — jobs execute inline. This is adequate because nothing currently dispatched is slow or external: notifications are database-only, and no real mail/SMS/payment provider is wired up. When a real provider is added, switch to `QUEUE_CONNECTION=database` and drive the worker from cron:

```
* * * * * cd /home2/innovx5x/shop.allsoft.online && /opt/cpanel/ea-php83/root/usr/bin/php artisan queue:work --stop-when-empty --max-time=55 >> /dev/null 2>&1
```

## Verified on the live deployment

Checked by actually hitting production, not inferred:

- `https://shop.allsoft.online/` → 200, renders GroceryHub storefront
- `http://` → 301 → `https://`
- `/up` health check → 200
- `.env` → 406, `/.git/config`, `/composer.json`, `/vendor/autoload.php`, `/storage/logs/laravel.log` → 404 (docroot is `public/`, so none are reachable)
- `POST /api/v1/auth/login` with the demo customer → token issued
- `GET /api/v1/products` → paginated catalog from live MySQL
- `POST /api/v1/cart/items` → cart updated
- `POST /api/v1/checkout` → **real order created** (`GH20261003Z2SAII`, ₹2442.44, COD, pending)
- Stock decremented 174 → 172 on that order, confirming the inventory ledger works against MySQL

Two production-only bugs were found and fixed during this process — see the commit log: a route-name collision that broke `route:cache` (so the app couldn't be cache-optimized at all), and money fields serializing as IEEE754 float noise because this host sets `serialize_precision=100`.
